
Aapke models ke hisaab se **Broker** me `password` aur `role` hai, jabki **Customer** model me `password` nahi hai, isliye abhi **customer login/register nahi**, balki **broker customer create karta hai**. Policy aur PolicyAssignment me PDF/document aur signing flow already supported hai.    

---

# Base URL

```txt
http://localhost:3000
```

---

# 1) Public / Auth routes

## 1.1 Register Broker

```txt
POST /api/public
```

### Body (JSON)

```json
{
  "name": "Akhilesh Broker",
  "email": "broker@example.com",
  "password": "123456"
}
```

### Notes

* Agar aapka `server/api/public/index.post.ts` register handle kar raha hai, to ye route use hoga.
* `role` backend me default `"Broker"` ho sakta hai.

---

## 1.2 Login Broker

```txt
POST /api/public/login
```

### Body (JSON)

```json
{
  "email": "broker@example.com",
  "password": "123456"
}
```

### Notes

* Success ke baad token milega.
* Protected routes ke liye header me token bhejna hoga.

### Header

```txt
Authorization: Bearer <token>
```

---

## 1.3 Get My Profile

```txt
GET /api/profile
```

### Notes

* Ye authenticated route hai.
* Broker ka profile return karega.
* Body nahi lagega.

### Header

```txt
Authorization: Bearer <token>
```

---

# 2) Customer routes (Broker Protected)

## 2.1 Create Customer

```txt
POST /api/broker/customer/create
```

### Body (JSON)

```json
{
  "name": "Rahul Sharma",
  "email": "rahul@example.com",
  "phone": "9876543210",
  "address": "Delhi"
}
```

### Notes

* `brokerId` body me mat bhejo.
* Backend me logged-in broker se set hoga.

### Header

```txt
Authorization: Bearer <token>
```

---

## 2.2 Get All Customers

```txt
GET /api/broker/customer?page=1&limit=10
```

### Notes

* Broker ke customers list honge.
* Pagination query supported.

### Header

```txt
Authorization: Bearer <token>
```

---

# 3) Policy routes (Broker Protected)

## 3.1 Create Policy

```txt
POST /api/broker/policy/create
```

### If JSON only

```json
{
  "title": "Health Insurance",
  "premium": 5000,
  "coverage": "500000",
  "duration": "1 year"
}
```



### If PDF upload

Use `form-data` in Postman:

| Key      | Value            |
| -------- | ---------------- |
| title    | Health Insurance |
| premium  | 5000             |
| coverage | 500000           |
| duration | 1 year           |
| document | [file]           |

### Notes

* PDF/document field ka naam `document` rakho.
* `brokerId` backend set karega.
* Policy model me `documentUrl` aur `documentPublicId` save honge. 

### Header

```txt
Authorization: Bearer <token>
```

---

## 3.2 Get All Policies

```txt
GET /api/broker/policy?page=1&limit=10
```

### Header

```txt
Authorization: Bearer <token>
```

# 4) Policy Assignment routes (Broker Protected)

Policy assignment schema me `brokerId`, `customerId`, `policyId`, `status`, `signingToken`, `signedAt`, `signedPdfUrl`, `signedFilePublicId` hai. Same broker + same customer + same policy combination unique hona chahiye. 

---

## 4.1 Assign Policy to Customer

```txt
POST /api/broker/policy-assignment/create
```

### Body (JSON)

```json
{
  "customerId": "CUSTOMER_OBJECT_ID",
  "policyId": "POLICY_OBJECT_ID"
}
```

### Notes

* `brokerId` body me mat bhejo.
* Backend logged-in broker se lega.
* Agar same broker ne same customer ko same policy already assign ki, to error aana chahiye.

### Header

```txt
Authorization: Bearer <token>
```

---

## 4.2 Get All Assigned Policies

```txt
GET /api/broker/policy-assignment?page=1&limit=10
```

### Notes

* Broker wise assignments list.
* Populate `customerId` aur `policyId`.

### Header

```txt
Authorization: Bearer <token>
```

---

## 4.3 Get Single Assignment

```txt
GET /api/broker/policy-assignment/:id
```

### Header

```txt
Authorization: Bearer <token>
```

# 5) Public signing routes

Ye routes customer ke liye public honge.

---

## 5.1 Open Signing Link

```txt
GET /api/public/sign/:token
```

### Example

```txt
GET /api/public/sign/7e1b1b5b-4d5c-4bda-9d2f-2a2e6c8f2d11
```

### Notes

* Is route se assignment detail milega.
* Token valid hona chahiye.
* Ye route public hai, auth header nahi lagega.

---

## 5.2 Submit Signed File

```txt
POST /api/public/sign/:token
```

### Body

Use `form-data`

| Key        | Value  |
| ---------- | ------ |
| signedFile | [file] |

### Notes

* Signed file upload ho jayega.
* Backend status `signed` karega.
* `signedAt`, `signedPdfUrl`, `signedFilePublicId` update honge.

# 7) Simple Postman body summary

## Register/Login

* `POST /api/public`
* `POST /api/public/login`
* Body: JSON

## Profile

* `GET /api/profile`
* No body

## Customer

* `POST /api/broker/customer/create`
* `PUT /api/broker/customer/:id`
* Body: JSON

## Policy

* `POST /api/broker/policy/create`
* `PUT /api/broker/policy/:id`
* Body: JSON or `form-data` if file included

## Assignment

* `POST /api/broker/policy-assignment/create`
* Body: JSON

## Public sign

* `GET /api/public/sign/:token`
* `POST /api/public/sign/:token`
* Body: `form-data`
